
Использование Visual Studio для программирования на языке ассемблера.
Для создания кода на языке ассемблера в Visual Studio необходимо активировать пользовательские правила построения (поставляются вместе с Visual Studio) файлов с раширением .asm.
Для подсветки синтаксиса в редакторе можно установить расширение AsmHighlighter из каталога \\dc1\doc\Matkin\asm\3 курс\soft.


Функции на языке ассемблера masm.

Для создания функции на языке ассемблера достаточно указать метку с именем функции в её начале и написать код. В этом случае необходимо будет самостоятельно реализовывать всю функциональность функции. В языке ассемблера masm предусмотрена специальная директива для определения функций.

Синтаксис объявления функций:

SomeFun proc [langtype] [USES reglist] arg1:arg1_type, arg2:arg2_type, ...

    local var1:var1_type
    local var2:var2_type
    local buf[count]:buf_type

    ret
SomeFun endp

При использовании директивы proc компилятор самостоятельно может генерировать некоторый стандартный код, облегчая программирование функций.
Директива proc позволяет указать имена аргументов и локальных переменных. В коде функции мы можем обращаться к ним через указанные имена, а компилятор будет преобразовывать их в обращения через регистр ebp по соответствующим смещениям. Через двоеточие от локальных переменных и аргументов указывается их тип (byte, word, dword, ptr, ...). Для аргументов типом почти всегда будет dword.

Если функции нужен стековый фрейм (если у функции есть аргументы или локальные переменные), то в начале функции будет сформирован стандартный пролог:
push ebp
mov ebp, esp
sub esp, xx
Размер резервируемой памяти (сколько вычетается из esp) высчитывается компилятором из объявленных локальных переменных.
В месте указания инструкции ret будет сформирован стандартный эпилог:
leave
ret / retn N

Параметр langtype в директиве proc задаёт соглашение о вызовах (c, stdcall). Исходя из соглашения определяются смещения для доступа к аргументам функции и инструкция возврата из функции (ret или retn N). Если его не указать, то будет использовано соглашение о вызовах по умолчанию, указанное в директиве .model или флагом компиляции.

Некоторые соглашения накладывают ограничения на возможность изменения регистров внутри функций. Т.е. при выходе из функций значения некоторых регистров должны быть теми же, что и на входе. Если внутри функции эти регистры изменяются, то необходимо в начале функции их сохранить, а перед выходом востановить. Этот код может сгенерировать компилятор. Для этого директивой USES указываем (через пробел) имена нужных регистров.
